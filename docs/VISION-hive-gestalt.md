# 项目展望：蜂巢 + 格式塔复合认知系统

> 状态：**思路稿**（2026-11-07）。这是方向稿，不是排期表；三块留白（调度规则 / 数据标签 / 触发逻辑）等后面接着聊。
> 工程落地切分（核心/插件边界、适配器四档、待拍板项）见 [ROADMAP.md](ROADMAP.md)。

## 一句话
一个记忆机库 + 一群能互相质证的蜂，加一个把碎片编织成人的归档器。不是"更大的记忆库"，是"记忆怎么长成判断力"。

## 1. 蜂巢（Hive）
多 Agent 蜂节点围着同一个机库转。

- **蜂节点**：每个 agent 是一个蜂 —— 一次会话、一个常驻客户端、一个跑批任务都算。
- **临时记忆分片**：每个蜂有自己的工作区（scratch），存当天/当轮的想法、中间结论、失败尝试。
- **互相透明可读**：蜂 A 能直接读蜂 B 的分片，不靠转发。
- **写权收口**：只有 dream 任务有权限向机库（主记忆）写入；普通蜂只能写自己的分片。
- **交叉质证**：多条蜂对同一事实说法不一致时走质证，过滤假说与矛盾，胜出的才归档。

为什么要收口：现在 agent 走 MCP `retain` 能直接写库（`proposal` 只是缓一道），实测过"后来者覆盖前者"的污染。做法是把写入变成"提案 → 质证 → 归档"的单向漏斗。

跟现状的接口：`proposal` 状态 + `mvapprove`（提案骨架）、`scope`/`project_id`（承载哪个蜂/哪个工作区）、`supersede`（裁决表达）、`memory_authority`（治理层权威分级）。

## 2. 格式塔（Gestalt）
dream 归档环节的融合器。输入是校验通过的碎片，输出三件事：

1. **整理**：去重、合并同义、把碎句变陈述。
2. **时序串联**：按发生时间（不是入库时间）把零散事实连成线。
3. **编织**：画像（这个人是谁、在意什么、怎么说话）／编年史（年月日逐级压缩）／事实卡片（可检索可引用的原子断言）。

**完形强度开关**控制脑补幅度：低=只摆事实串联；中=允许归纳共性；高=允许补全叙事。原则是**脑补必须可追溯** —— 编出来的每条结论都要挂着证据碎片，强度越高证据要求越严。

跟现状的接口：`dream.py`（常驻池 + dreams/dream_runs）、`chronicle.py`/`rollup.py`/`profile.py`/`selfnote.py`（编织器雏形）、`procedures`/`focus`/`scenes`（套路/未完成/场景三种产物形态）。

## 3. 基座：memvault（复用，不重写）
- **MCP**：`recall / retain / stats / report` —— 蜂节点的标准接入面。
- **DLP 脱敏**：入库前凭据/敏感信息处理（`scrub.py`）。
- **provider 适配器**：`providers`/`provider_models` + 分任务路由（learn/dream/summary 各走各的 key 与模型）。
- **dream 任务**：定时器 + 手动触发两条入口。
- **检索打分**：`0.65*vec + 0.35*bm25` + 温度衰减 + `supersedes` 降权 + 自适应 BM25 底线。

基座不做：蜂的调度、质证裁决、编织。它只负责存、取、给分、给证据。

## 4. 数据流草稿
```
蜂（会话/批任务） --写--> 临时分片(scope=agent:<name>)
     --质证(同槽位不同取值)--> 质证队列(conflicts)
     --裁决(证据/权威/时间)--> dream 归档(唯一写机库的通道)
     --融合(整理→串联→编织)--> 机库(事实卡/画像/编年史)
     --只读--> 蜂下一轮 recall
```

## 5. 待细化（留白）
**5.1 调度规则**：蜂何时交分片（轮末/字数/定时/显式）；质证谁发起；多蜂说同一件事按票数还是证据；蜂离线后分片何时作废。

**5.2 数据标签**：至少能回答"谁说的/何时说的/什么场景/可不可信"。候选维度：`source`(human/agent:<name>/dream/imported)、`stage`(scratch/proposal/verified/archived/superseded)、`confidence`(证据条数+权威+是否质证)、`temporal`(发生时 vs 入库时，现两列语义常混)、`scope`(global/project:<id>/agent:<name>/session:<id>)。

**5.3 触发逻辑**：归档按 dream tick 还是攒够 N 条；完形强度默认档与谁能改；矛盾时先归档再挂待裁决还是打断；什么情况允许把已归档的卡退回分片重审。

**5.4 开放问题**：蜂的"透明可读"要不要访问控制；画像/编年史重写频率与旧版保留；质证失败的假说要不要留（"我们曾以为是 X"本身是信息）；强度调高后怎么防止脑补反哺成事实。

## 6. 演进阶段（粗）

|---|---|---|
| P0 | 单库 + MCP + 打分 + dream 雏形 | 已具备 |

## 7. 一句话原则
> **机库只收经过质证的东西；编出来的东西必须能顺着证据链走回去。**
